# Как добавить запись

Каталог — это папка с файлами. Одна запись — один YAML-файл в `data/`. Добавить запись значит скопировать шаблон, заполнить его и открыть PR. Вёрстку и код сайта для этого трогать не нужно.

Если GitHub не твой инструмент, есть два пути короче:

- кинь ссылку в [чат сообщества](https://t.me/jtprogru_chat) и напиши, что это и зачем оно сообществу;
- заполни [форму](https://github.com/jtprogru/sre.moscow/issues/new/choose): она задаёт те же вопросы, что и файл записи.

В обоих случаях файл оформят кураторы.

Что подходит каталогу, а что нет, описано в [CRITERIA.md](CRITERIA.md). Прочитай раздел про свой тип записи до того, как заполнять файл: это быстрее, чем переделывать после ревью. В репозитории и в чате действует [Кодекс поведения](CODE_OF_CONDUCT.md).

## Путь за пять минут

1. Сделай форк и склонируй его.
2. Скопируй шаблон в нужную папку и дай файлу имя по правилу из таблицы ниже.
3. Заполни поля. В шаблоне к каждому есть комментарий; комментарии после заполнения удали.
4. Открой каждую ссылку из записи и убедись, что она ведёт туда, куда подписана.
5. Запусти `make check`. Если что-то не так, проверка назовёт файл и поле.
6. Открой PR.

```bash
cp templates/event.yaml data/events/2026-11-sre-meetup-moscow.yaml
$EDITOR data/events/2026-11-sre-meetup-moscow.yaml
make check
```

Для `make check` нужен [bun](https://bun.sh/) версии 1.4 или новее. Ставить его необязательно: те же проверки запустятся в PR сами, просто ответ придёт на пару минут позже.

| Что добавляешь | Шаблон | Куда положить | Имя файла |
| -------------- | ------ | ------------- | --------- |
| Чат, канал, подкаст | `templates/community.yaml` | `data/communities/` | `<slug>.yaml` |
| Доклад | `templates/talk.yaml` | `data/talks/` | `<год>-<slug>.yaml` |
| Событие | `templates/event.yaml` | `data/events/` | `<гггг-мм>-<slug>.yaml` |
| Компания или организатор | `templates/organizer.yaml` | `data/organizers/` | `<slug>.yaml` |
| Свой профиль | `templates/person.yaml` | `data/people/` | `<slug>.yaml` |

`<slug>` — латиница, цифры и дефисы в нижнем регистре: `sre-meetup-moscow`. Имя файла становится адресом записи на сайте, поэтому менять его после публикации не стоит.

## Чат, канал, подкаст

Шаблон: [`templates/community.yaml`](templates/community.yaml).

`description` — до 200 символов о том, что там обсуждают и с каким вопросом туда идти. Для Telegram нужна публичная ссылка вида `https://t.me/имя`: пригласительные ссылки со временем протухают.

Поле `verified` — дата, когда ссылку открывали в последний раз. При добавлении оно совпадает с `added`. Записи, которые не сверяли дольше полугода, проверка выводит списком: это рабочий список кураторов, а не ошибка.

## Доклад

Шаблон: [`templates/talk.yaml`](templates/talk.yaml).

Имя спикера пиши так, как оно указано на странице доклада. Строку `person` добавляй, только если у спикера уже есть профиль в `data/people/`: создавать профиль за другого человека нельзя, а доклад прекрасно живёт и без него.

Главное поле — `why`. Одна фраза о том, зачем это смотреть, своими словами. «Доклад о мониторинге» не годится, «показывает, как сократить алерты втрое, не потеряв ни одного инцидента» — годится.

Если событие, где прозвучал доклад, есть в `data/events/`, укажи его в `event.ref`: доклад появится на странице организатора.

Выпуск подкаста добавляется так же. В `event.name` пиши название подкаста с номером выпуска, в `speakers` — участников со страницы выпуска.

## Событие

Шаблон: [`templates/event.yaml`](templates/event.yaml).

Дата и время. Если время неизвестно, пиши дату: `start: 2026-11-05`. Если известно, пиши дату и время со смещением и обязательно в кавычках: `start: "2026-11-05T19:00:00+03:00"`. Без кавычек YAML приведёт время к UTC, смещение потеряется, и сборка об этом скажет. Время указывается местное для события, `+03:00` — это Москва.

`url` — страница именно этого события. Главная страница организатора не подходит: по ней через месяц будет уже другое событие.

Если организатор есть в `data/organizers/`, укажи его в `organizer.ref`: событие появится в его карточке. Если нет, оставь только `name`. Заводить карточку организатора ради одного события не обязательно.

Прошедшие события удалять не нужно: они сами переезжают в архив.

К прошедшему событию можно дописать разборы — тексты участников о том, что там было. Это блок `recaps` в файле события, пример есть в шаблоне. `title` и `author.name` бери со страницы текста. `author.person` указывай, только если у автора уже есть профиль в `data/people/`: заводить профиль ради разбора не нужно. Что считается разбором — в [CRITERIA.md](CRITERIA.md#разборы).

## Компания или организатор

Шаблон: [`templates/organizer.yaml`](templates/organizer.yaml).

Запись отвечает на вопрос «куда смотреть, чтобы не пропустить их события». Поэтому хотя бы одна ссылка вида `events` обязательна — страница с расписанием или анонсами. Остальные виды ссылок: `recordings` для записей докладов, `announcements` для канала или рассылки с анонсами, `cfp` для приёма заявок.

Каждую ссылку открой перед добавлением. Адреса страниц событий меняются чаще, чем кажется, а угаданный по названию адрес обычно ведёт на главную или в никуда.

Размещение бесплатное и не продаётся, порядок на сайте алфавитный. Подробнее — в [CRITERIA.md](CRITERIA.md#компании-и-организаторы).

## Свой профиль

Шаблон: [`templates/person.yaml`](templates/person.yaml).

Профиль добавляется только свой или с явного согласия человека. Если открываешь PR сам, в `consent.by` пиши `self`. Если вносишь профиль за коллегу, который согласился, в `consent.by` пишется GitHub-логин куратора, которому он это подтвердил, поэтому такой PR сначала обсуди в чате.

Фото добавляется строкой `photo` со ссылкой на картинку, например `https://github.com/<логин>.png`. Сайт забирает её при сборке и раздаёт уменьшенную копию со своего адреса. Без этой строки в профиле стоят инициалы.

Указывай только те контакты, по которым готов отвечать. Убрать профиль можно в любой момент: [форма](https://github.com/jtprogru/sre.moscow/issues/new?template=fix.yml) или PR с удалением файла.

## Темы

В поле `topics` допустимы только id из [`data/topics.yaml`](data/topics.yaml). Словарь закрытый намеренно: иначе через месяц в нём будут «observability», «o11y» и «наблюдаемость» как три разные темы.

Если подходящей темы нет, выбери ближайшую и предложи новую отдельным PR в `data/topics.yaml`.

## Исправить или удалить

Ссылка умерла, дата поменялась, чат закрылся — пришли PR с правкой файла или заполни [форму](https://github.com/jtprogru/sre.moscow/issues/new?template=fix.yml). Правка в одну строку здесь такой же нормальный вклад, как новая запись.

Если сверил ссылки в записи и они живы, обнови `verified` на сегодняшнюю дату. Это тоже вклад, и довольно нужный.

## Что проверяет `make check`

Команда одна и та же локально и в CI.

- Форму записи: обязательные поля, допустимые значения, длины, опечатки в названиях полей. Это схема в [`src/content.config.ts`](src/content.config.ts).
- Связи и даты: дубли адресов внутри раздела, конец события раньше начала, дедлайн CFP позже события, разбор у события, которое ещё не началось, ссылки на несуществующие записи, организатор без страницы событий, профиль без согласия. Это [`tools/check-data.mjs`](tools/check-data.mjs).
- Собранный календарь `events.ics`, контраст цветов и разметку markdown.

## Если хочешь править сам сайт

```bash
make install   # зависимости
make dev       # http://localhost:4321/
make check     # всё, что гоняет CI
make ui-check  # вёрстка в браузерах, если менял стили или разметку
```

| Путь | За что отвечает |
| ---- | --------------- |
| `data/` | записи каталога, по файлу на запись |
| `data/topics.yaml` | закрытый словарь тем |
| `templates/` | заготовки записей |
| `src/content.config.ts` | схемы коллекций, единственное место истины о форме данных |
| `src/pages/` | страницы, календарь `events.ics` и `rss.xml` |
| `src/lib/` | работа с датами, подписи, общие запросы к каталогу |
| `src/styles/tokens.css` | цветовые роли и шкалы |
| `src/brand/` | знак, сова, фавикон и иконки: рисуются при сборке, условия — в `LICENSE-BRAND` |
| `tools/` | проверки данных, календаря, контраста, бренда и вёрстки |

Сайт полностью статический: без бэкенда, базы и клиентского фреймворка. Фильтры работают на data-атрибутах и небольшом скрипте, без JS страница показывает весь список. Прежде чем добавлять зависимость или клиентский код, открой issue: чем тоньше сайт, тем дольше он проживёт без присмотра.

Коммиты — в формате [Conventional Commits](https://www.conventionalcommits.org/ru/): `feat(data): add sre meetup moscow`, `fix(events): correct cfp deadline`.
