# sre.moscow

[sre.moscow](https://sre.moscow/) — каталог SRE-сообщества: что смотреть, где общаются, к кому идти с вопросом и куда приехать.

Для тех, кто занимается надёжностью и эксплуатацией, от студентов последних курсов до лидов. Охват — русскоязычное сообщество плюс международные площадки, где надёжность основная тема.

## Что внутри

| Раздел | На какой вопрос отвечает |
| ------ | ------------------------ |
| [Доклады](https://sre.moscow/talks/) | Что посмотреть и зачем |
| [Сообщества](https://sre.moscow/communities/) | Где задать вопрос и что читать |
| [Люди](https://sre.moscow/people/) | К кому можно обратиться |
| [События](https://sre.moscow/events/) | Куда стоит приехать и что осталось от прошедшего |
| [Организаторы](https://sre.moscow/organizers/) | Куда смотреть, чтобы не пропустить анонс |

Порядок не случайный. Впереди то, что отбирают люди и чего не соберёт автоматическая афиша: у доклада сказано, зачем его смотреть, у сообщества — с чем туда идти, человек сам разрешил к себе обращаться.

События идут следом и полнотой не занимаются. Предстоящие — короткий отбор с подпиской: [`events.ics`](https://sre.moscow/events.ics) открывается в Google, Apple и любом другом календаре. Прошедшее событие собирает то, что от него осталось: доклады из каталога и разборы участников. За полной афишей стоит идти к организаторам: их страницы почти не устаревают и полезны, даже когда конкретный митап сюда никто не добавил.

## Независимость

Независимое сообщество инженеров. Не принадлежит ни одной компании и никем не спонсируется.

- Место в каталоге не продаётся.
- Мейнтейнеры участвуют как частные лица.
- Каталог ведёт автор блога «Мишка на сервере», и главная кнопка сайта ведёт в его чат.

## Чем сайт не является

Это не афиша мероприятий, не доска вакансий, не рекламная площадка и не рейтинг. Размещение бесплатное и не продаётся, порядок записей алфавитный или по дате.

Это не полный список всего про DevOps. Каталог ценен отбором: у доклада написано, зачем его смотреть, у организатора — зачем за ним следить. Что подходит, а что нет, описано в [CRITERIA.md](CRITERIA.md).

Это не учебник. Чему и в каком порядке учиться, разбирает соседний проект [The Way of SRE](https://github.com/jtprogru/The-Way-of-SRE).

## Как добавить запись

Каталог пополняет сообщество. Одна запись — один файл в `data/`, шаблоны лежат в `templates/`.

```bash
cp templates/event.yaml data/events/2026-11-sre-meetup-moscow.yaml
$EDITOR data/events/2026-11-sre-meetup-moscow.yaml
make check
```

Без GitHub тоже можно: кинь ссылку в [чат сообщества](https://t.me/jtprogru_chat) или заполни [форму](https://github.com/jtprogru/sre.moscow/issues/new/choose). Подробности по каждому типу записи — в [CONTRIBUTING.md](CONTRIBUTING.md).

Профили людей добавляются только с их согласия и удаляются по первому запросу. Правило и порядок удаления — в [CRITERIA.md](CRITERIA.md#люди).

## Локальный запуск

Нужен [bun](https://bun.sh/) 1.4 или новее и `make`.

```bash
make install   # зависимости
make dev       # http://localhost:4321/
make check     # всё, что гоняет CI на PR
make ui-check  # вёрстка в браузерах: нужны Node и движки Playwright
make help      # остальные цели
```

`Makefile` — единственная точка входа: workflow в CI зовут те же цели, что и ты локально.

## Как устроено

Astro собирает статический сайт из YAML-файлов. Бэкенда, базы, CMS и авторизации нет, модерацией служит ревью PR.

```text
data/                    записи каталога, по файлу на запись
  topics.yaml            закрытый словарь тем
templates/               заготовки записей
src/content.config.ts    схемы коллекций
src/pages/               страницы, events.ics, rss.xml, индекс поиска search.json
src/lib/site.ts          название, слоган и заявление о независимости
src/styles/tokens.css    цвет, шрифты и шкалы
tools/                   проверки данных, календаря, контраста и текстов
```

Сайт пересобирается при каждом изменении в `main` и раз в сутки по расписанию, чтобы прошедшие события уезжали в архив.
